# Como contribuir

1. Descreva o objetivo e o impacto operacional antes de alterar código ou dados.
2. Não publique credenciais, planilhas, dados pessoais ou exportações de produção.
3. Valide a alteração com testes ou uma conferência equivalente antes de abrir pull request.
4. Use títulos claros e relacione issues quando houver.
5. Alterações em banco, permissões, autenticação e deploy exigem revisão explícita.
6. Novos commits devem usar um e-mail verificado no GitHub que atribua a contribuição à conta S4MSO21.
7. Antes do primeiro push em uma máquina, configure a identidade Git local e confira a atribuição no GitHub; não use identidade de outra pessoa, conta de IA ou e-mail temporário.
8. Não reescreva histórico já publicado apenas para alterar autoria sem uma decisão explícita de migração.
